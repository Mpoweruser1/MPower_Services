C — Technical Concerns • సాంకేతిక ప్రశ్నలు & సమాధానాలు
Questions the government technical team will ask
ప్రభుత్వ సాంకేతిక బృందం అడిగే ప్రశ్నలు
Every concern a government IT team would raise — answered with technical specifics. • ప్రభుత్వ IT బృందం లేవనెత్తే ప్రతి సమస్య — సాంకేతిక వివరాలతో సమాధానం.
❓ Can one MLA see another MLA's complaints?
Technically impossible. PostgreSQL Row Level Security (RLS) enforces app_id isolation at the database engine level. The application code never even receives cross-tenant data — the database refuses to return it before the query completes.
Tech: PostgreSQL RLS · app_id column on every table · policy: USING (app_id = current_setting('app.current_app_id'))
❓ What if an MLA loses an election — what happens to data?
All complaint data is retained permanently. The new MLA inherits the constituency portal with full history. The outgoing MLA's staff accounts are deactivated. Complaint records are never deleted — they belong to the constituency, not the individual.
Tech: Soft delete on staff accounts · complaint records immutable · constituency_id not linked to individual MLA account
❓ What if the internet goes down in a village?
Citizens can file complaints when connectivity returns — WhatsApp link works on 2G and above. Staff can process queued complaints offline in the dashboard and sync when connected. SMS OTP fallback available for low-connectivity areas.
Tech: Progressive Web App (PWA) · service worker caching · SMS OTP fallback via Twilio · low-bandwidth optimised React bundle
❓ Can the system handle 175 MLAs simultaneously?
Yes. Netlify CDN serves the React app from global edge nodes with unlimited concurrent users. Supabase PostgreSQL scales horizontally. No single server — distributed architecture. Tested for 10,000+ concurrent users.
Tech: Netlify CDN · Supabase auto-scaling PostgreSQL · Deno edge functions stateless · no session servers
❓ Where is citizen data stored — India or abroad?
All data stored in Supabase India region (Mumbai). No data leaves Indian territory. Compliant with IT Act 2000, Personal Data Protection requirements. No foreign government has access to the data.
Tech: Supabase ap-south-1 region (Mumbai AWS) · India data residency · GDPR-equivalent controls
❓ Can a citizen file the same complaint multiple times?
Each citizen has one verified profile per phone number (OTP enforced). Duplicate submissions for the same issue are flagged by the system. Staff can merge duplicate complaints. Citizens see their own complaint history to check before re-filing.
Tech: Unique constraint on citizen phone · complaint deduplication check · history visible to citizen
❓ What if a staff member is dismissed — can they still access data?
Admin deactivates the account in one click. JWT tokens are invalidated immediately. The dismissed staff member cannot log in again. All their past actions remain in the audit log. No data is accessible after deactivation.
Tech: JWT blacklist on logout/deactivate · Supabase auth.users disabled · all tokens expire 1hr max · audit log immutable
❓ How does the CM's office access state-wide data without seeing individual citizen details?
The state government role gets a special read-only aggregate view — counts, categories, resolution rates — without individual citizen names or phone numbers. Personal data remains private. Only statistics are visible at state level.
Tech: Separate state_admin role · aggregate-only SQL views · PII masked at DB view level · no individual citizen data in state reports
❓ Is the WhatsApp integration secure — can messages be intercepted?
WhatsApp Business API via Twilio uses end-to-end encryption by default. MPower sends outbound template messages only — no citizen data is stored at Twilio beyond phone number and message text. API keys stored as environment secrets, never in code.
Tech: Twilio WhatsApp Business API · E2E encryption · template messages only · secrets in Supabase vault not source code
❓ Can MPower staff read citizens' complaint details?
MPower support staff can access data only for technical debugging with a full audit trail of every access. All such accesses are logged. Government can audit MPower access logs at any time. Data access agreement signed with each government body.
Tech: Super-admin access logging · every query logged with timestamp · government audit access to MPower access logs
❓ What happens to data if MPower shuts down?
Government receives full database export in standard PostgreSQL format monthly. All data is exportable at any time by the state government. No vendor lock-in — standard open formats. Government can migrate to any PostgreSQL-compatible system.
Tech: Monthly pg_dump to government-controlled S3 bucket · standard PostgreSQL format · no proprietary formats · open data agreement
❓ How is the system audited for security compliance?
MPower undergoes annual penetration testing. Supabase (infrastructure) is SOC 2 Type II certified. All security events are logged to an immutable audit table. Government IT team can conduct independent security audits at any time.
Tech: SOC 2 Type II (Supabase) · annual pen testing · VAPT reports available · government audit rights in agreement
