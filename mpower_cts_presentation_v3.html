05 — Security & Technology • భద్రత & సాంకేతికత
Bank-grade security protecting every citizen
ప్రతి పౌరుడిని రక్షించే బ్యాంక్-స్థాయి భద్రత
Five independent security layers. Every complaint is encrypted, verified, and audit-logged. Citizens' personal data is never shared. • 5 స్వతంత్ర భద్రతా పొరలు. పూర్తి గోప్యత.
Security layers • భద్రతా పొరలు
🔒
TLS 1.3 Encryption in transit
TLS 1.3
All data between citizen phone and server is encrypted with TLS 1.3 — the same standard used by banks. No data can be intercepted in transit.
పౌరుడి ఫోన్ నుండి సర్వర్ వరకు అన్ని డేటా TLS 1.3 తో గుప్తీకరించబడింది — బ్యాంకులు ఉపయోగించే అదే ప్రమాణం.
🗄️
AES-256 Encryption at rest
AES-256
All complaint data stored in PostgreSQL is encrypted at rest using AES-256 — military-grade encryption. Even if the database server were physically accessed, data is unreadable.
PostgreSQL లో నిల్వ చేయబడిన అన్ని ఫిర్యాదు డేటా AES-256 తో గుప్తీకరించబడింది — సైనిక స్థాయి గుప్తీకరణ.
🔑
JWT Authentication
JWT · RS256
Every staff login issues a signed JWT (JSON Web Token) using RS256 algorithm. Tokens expire after 1 hour. Cannot be forged or reused after expiry.
ప్రతి సిబ్బంది లాగిన్ RS256 అల్గారిథమ్ తో సంతకం చేయబడిన JWT జారీ చేస్తుంది. 1 గంట తర్వాత గడువు ముగుస్తుంది.
📱
OTP Mobile Verification
6-digit · 10min
Citizens verify their mobile number via 6-digit OTP before filing any complaint. Single-use, 10-minute expiry. No anonymous or fake submissions possible.
పౌరులు ఫిర్యాదు దాఖలు చేయడానికి ముందు 6-అంకెల OTP తో మొబైల్ నంబర్ ధృవీకరించాలి. నకిలీ ఫిర్యాదులు సాధ్యం కాదు.
Database security • డేటాబేస్ భద్రత
🛡️
Row Level Security (RLS)
PostgreSQL RLS
Database-level policy engine. Even if application code has a bug, the database itself refuses to return data that the requesting user is not authorised to see. Constituency A can never access Constituency B's complaints — enforced at DB level, not just application level.
డేటాబేస్ స్థాయి పాలసీ ఇంజిన్. నియోజకవర్గం A నియోజకవర్గం B యొక్క ఫిర్యాదులను ఎప్పటికీ చూడలేదు.
👥
Role-based Access Control
RBAC · 12 roles
12 distinct roles: grievance_staff, grievance_admin, developer, and more. Each role sees only permitted screens. A junior staff member cannot access admin reports or approve staff registrations.
12 పాత్రలు. జూనియర్ సిబ్బంది అడ్మిన్ నివేదికలను యాక్సెస్ చేయలేరు.
📋
SHA-256 Audit Trail
SHA-256 hash
Every action — complaint stage change, staff login, evidence upload — is logged with user ID, timestamp, and a SHA-256 content hash. Records cannot be modified. Full audit trail for RTI and government inspections.
ప్రతి చర్య SHA-256 హాష్ తో లాగ్ చేయబడుతుంది. RTI మరియు ప్రభుత్వ తనిఖీలకు పూర్తి ఆడిట్ రికార్డు.
🇮🇳
India data residency
Supabase · India region
All citizen data stored in India. No foreign servers. No data leaves Indian territory. Compliant with India's IT Act and data localisation requirements.
అన్ని పౌర డేటా భారతదేశంలో నిల్వ చేయబడింది. విదేశీ సర్వర్లు లేవు. IT చట్టం మరియు డేటా లోకలైజేషన్ అవసరాలకు అనుకూలం.
